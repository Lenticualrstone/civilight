## Partial

- `SavedUiState` (§2.13: route, selection, sheet, viewports) is not modelled here; it is navigation/UI state (SavedStateHandle). Canvas and map viewports and the remembered world tab are in `ProjectViewFile`.
- `GeneratedMapRecord.result` and history `resultRef` are opaque JSON (the generator owns their geometry).
- `ProjectFileSet.decode` isolates failures per file (`failedPaths`); only `project.json` and `story/index.json` are fatal. It does not repair cross-file references to rows of a lost file; the importer decides what to show.
- `ProjectFileSet` is the structural split only; export rules (name tags for trashed references, blob selection, hidden records, encryption, manifest hashes, `preview.webp`) belong to the exporter.

## Defaults used

- **Required properties are always written.** The Json uses `encodeDefaults = false` (as instructed); properties that §7 lists as required carry `@EncodeDefault` (`hidden`, `doneMarked`, `anchorState`, `kind`/`mode` defaults, `runs`, `fields`, bookkeeping, file-unit arrays …). Optional ones equal to their default are omitted.
- **Every JSON object type of the file model has `ext: JsonObject?`** (nested value objects too: `VoiceState`, `SlotValue`, `DocBlock`, `LinkTarget`, `Crop` …), so a newer minor version adding a nested property never fails to read. Unknown properties live in `ext["_unknown"]`. Exception: `Blob` (see Spec conflicts) drops unknown properties.
- **Zero-field union variants** (`TextRun.Break`, `Anchor.Unplaced`, `SceneTime.None`, `LensPoint.Latest`) are data objects; unknown properties on them are dropped.
- **Always use `CivilightJson.decode/encode`** (or the element variants). The raw `CivilightJson.json` is strict and does not fold unknown properties.
- **App-only enums** (settings, view state, runtime) are closed enums written lowerCamelCase; an unknown value falls back to the enum's default instead of being kept.
- **Read-time anchor resolution**: an anchor whose block or unit is not live (not yet relocated) ranks like its §5.5 relocation target (first live block after its old position, else unplaced); an anchor to a key not in the project is unplaced; a world-event anchor to a missing event sorts before every event; events without `worldDate` sort as the earliest events.
- **Lens**: `LensPoint.UnitEnd` of a non-live unit uses that unit's tour end; of an unknown unit reads as `최신`. An unknown `LensPoint` kind reads as `최신`.
- **PointRef**: modelled as `{kind: OpenEnum, unitKey}`; an unknown kind or unit resolves to +∞ (never visible).
- **Numbering unit** of a scene with no episode-level ancestor (inconsistent tree) is its topmost ancestor; 1-level structures use the project key.
- **Units whose parent row is missing** are treated as top level (in the index and in liveness).
- `Block.hasContent()` (집필 선): non-blank runs (breaks and whitespace do not count), any direction cue, or any non-blank choice option; an unknown kind counts by its runs.
- `StoryUnit.memo` is `String?` (absent = no memo), `transitionMode` is optional (`transitionModeOrNone`).
- `Project.travelModes` defaults to empty; project creation calls `TravelMode.defaults()` (도보 15/8, 말 40/8, 배 30/24).
- `WorldTime.mode` defaults to `yearOnly` (LIB-11 default), `fieldBundleAtCreation` to `basic`.
- `RecorderAudio.envelope` is base64 text, kept in the library store only and left out of `recorder.json`.
- `RecorderFileRecord` carries optional `deletedAt`/`trashEntryKey` so the working store can keep the library trash in the same shape; `RecorderFile.library(…, includeTrashed = true)` for the store, `false` for `.civilight-recorder`.
- `MergeRecord.kind` uses the name-tag kinds; `MovedRef` and `MergeChoice` typed from §2.11 (`{ownerKind, ownerKey, field}`, `{fieldDefKey} | {relationKey, slot}`).
- App-only project files: `_app/activity.json` = `ProjectActivityFile` (activity, day baselines, start checklist, export records), `_app/view.json` = `ProjectViewFile` (lens, script view, canvas/map viewports, world tab).
- `AppSettings.textSizeStep` is an integer step with 0 = `보통`.
- `ImageUse.crops` is keyed by the ratio's serial name (`r3x4`); use `cropFor(Ratio)`.
- `ScriptRestore.scrollAnchor` is the block key at the top of the viewport.
- Trash mirror of a live map holding a pin of a trashed place: `trash/maps/<key>.json` holds the map's fields with only the non-live pins.

## Spec conflicts

- **Where `DiscardedVoiceId` is stored**: §2.3 and §7.4 put it in the numbering unit file `story/<unit>.json`; §9's store table puts it in `story/index.json` ("DiscardedVoiceId of all units"). Chosen: the episode file (two sources, and §8.2 says the store holds the same file units as §7.2). `StoryIndexFile.discardedVoiceIds` is still read for tolerance and `ProjectIndex.discardedVoiceIds()` / `allDiscardedVoiceIds` include it. Note §9's placement would protect discarded IDs from a damaged episode file the way C-32 protects the counter; the product owner may want that.
- **`Blob.ext`**: §2.10 and §7.8 name the file extension `ext`, which is also the §1.3 extension-slot name every persisted object carries. Kept the §7.8 JSON name for the extension (`Blob.fileExt` in Kotlin, `@SerialName("ext")`); a blob therefore has no extension slot and unknown blob properties are dropped.
- **Fixture disagreement**: 20-story-time Fixture R puts R4 and R5 on block `#043`; 10-script fixture F1 puts R4 on `#042` and R5 on `#045` (and calls the `#043` record R1). Position tests use Fixture R; the 10-script cases were expressed with Fixture R's blocks.
- **`StoryUnit.memo`**: §2.2 types it `String` (non-null), §7.4 lists `memo?`. Modelled as optional.
- **`RecorderRecord.audio`**: §2.12 includes `envelope: ByteArray`; §7.10's `audio` object has no envelope. Kept in the library, left out of package files.
- **Trashed field definitions**: C-14 / §7.9 say normal files never hold non-live rows, but §7.9's mirror list has no `trash/project.json`, and `FieldDef` lives in `project.json`. `ProjectFileSet.split` writes trashed field definitions to `trash/project.json` (the project object with only those definitions; tags, relation kinds and travel modes empty) and `toDoc()` merges them back. An exporter without `휴지통도 포함` simply omits that file.
- **§0 vs §8.2**: §0/§1.6 describe the working store as the Room app DB; §8.2 (decision 2026-11-22) replaces it with a per-project document store. Followed §8.2.
