# 0.2.0 release gate checklist (emulator)

Closed checklist for the 0.2.0 release gate (`docs/status/0.2.0-scope.md` §10). Every item is run once and gets a result: `pass`, `fail` or `not run (reason)`. Nothing outside this list is required for release; anything else found on the way is triaged by the same rule and added to the results table at the end.

**Release rule.** Only a critical problem blocks the release. Critical means:
- crash or ANR
- data or input loss (typed text included, §8 of the scope included)
- a hidden or locked content leak
- the mic left on after pause or leaving the recorder
- anything unreachable, stuck or misleading
- a visible control that does nothing

Anything that hurts usability is critical. Cosmetic problems (spacing, colour, copy wording, motion feel) go to the 0.2.1 backlog. Each item below says `Blocker: yes` when its failure is critical by this rule, and `Blocker: no` when a failure is cosmetic by default. A `no` item still blocks if the failure seen is itself critical (for example a crash while checking a spacing item).

**Item fields.** Every item has:
- **Width:** `cover`, `inner` or `both`
- **Steps**
- **Expected**
- **Verify:** how the result is decided (adb, uiautomator dump, screenshot, JVM test)
- **Blocker:** yes or no

## 0. Setup

### 0.1 Rules for the run
- No Gradle while the emulator runs. Build and run all JVM tests with `tools/gw` first, close Gradle, then start the emulator. Never two Gradle runs at once (8 GB RAM).
- The device is the `Medium_Phone` AVD (API 37, 1080 × 2400, 420 dpi). There is no foldable AVD, so cover and inner widths are produced with `wm size` and `wm density` (below). A real hinge posture (half-open, tabletop, hinge occlusion) is **not covered** by this checklist; it is recorded as `not run` and is not a release blocker.
- 0.2.0 is installed over 0.1.0 with `adb install -r` only. Never `adb uninstall` after the 0.1.0 install in state A.
- The app has no `testTag`s. Every check reads `text` and `content-desc` from `uiautomator dump`. Icon buttons are matched by their accessibility name (content-desc), not by a visible word: `보내기`, `찾기 · 명령`, `표시`, `닫기`, `다음 씬 만들기`.
- `adb shell input text` types ASCII only. All typed test text uses ASCII sentinels such as `QA-W01-alpha`, so a grep of the dump proves the text is there. The Korean IME composing path is a separate manual item (W-16).
- Screens with `화면 캡처 가리기` on give a black `screencap`. Use the dump there, not a screenshot.

### 0.2 Inputs
- `$APK_010`: the released 0.1.0 APK. Get it with `gh release download v0.1.0 -p 'civilight-0.1.0.apk' -D "$OUT"`.
- `$APK_020`: the 0.2.0 release APK signed with the same release key.
- `$OUT`: a scratch folder outside the repo for dumps, screenshots and logs.
- `$PKG=io.github.lenticualrstone.civilight`

### 0.3 Helpers (bash)
```sh
PKG=io.github.lenticualrstone.civilight
dump()  { adb shell uiautomator dump /sdcard/ui.xml >/dev/null && adb pull -q /sdcard/ui.xml "$OUT/$1.xml"; }
has()   { grep -o -- "$2" "$OUT/$1.xml" | wc -l; }          # count of a text or content-desc in a dump
shot()  { adb exec-out screencap -p > "$OUT/$1.png"; }
tapt()  { python3 -I -c 'import sys,re,xml.etree.ElementTree as E
t=E.parse(sys.argv[1]);w=sys.argv[2]
for n in t.iter("node"):
  if w in (n.get("text"),n.get("content-desc")):
    a=list(map(int,re.findall(r"\d+",n.get("bounds"))));print((a[0]+a[2])//2,(a[1]+a[3])//2);break' "$OUT/$1.xml" "$2" | xargs adb shell input tap; }
ime()   { adb shell dumpsys input_method | grep -E "mInputShown|mIsInputViewShown|isInputViewShown"; }
crash() { adb logcat -d -b crash | grep -A20 "Process: $PKG"; adb logcat -d | grep -E "ANR in $PKG"; }
cover() { adb shell wm size 1080x2340; adb shell wm density 440; }   # about 393 dp wide
inner() { adb shell wm size 2208x2208; adb shell wm density 440; }   # about 803 dp wide
wmoff() { adb shell wm size reset; adb shell wm density reset; }
mic()   { echo "== audio"; adb shell dumpsys audio | grep -iE -A12 "record"
          echo "== flinger"; adb shell dumpsys media.audio_flinger | grep -iE -A4 "input|record"
          echo "== appops"; adb shell cmd appops get $PKG RECORD_AUDIO
          echo "== services"; adb shell dumpsys activity services $PKG | grep -E "ServiceRecord|isForeground|foregroundServiceType"; }
calm()  { for k in window_animation_scale transition_animation_scale animator_duration_scale; do adb shell settings put global $k 0; done; }
lively(){ for k in window_animation_scale transition_animation_scale animator_duration_scale; do adb shell settings put global $k 1; done; }
```
- Before each section: `adb logcat -c`. After each section: `crash > "$OUT/<section>-crash.txt"`.
- Rotation: `adb shell settings put system accelerometer_rotation 0`, then `adb shell settings put system user_rotation 1` (landscape) or `0` (portrait).
- Fold during a step: switch `cover` to `inner` (or back) while the screen is open. The app handles size changes itself (`configChanges`), so this exercises the same path as a fold.

### 0.4 Device states
- **State A (upgraded):** a clean emulator (wipe data in AVD manager), 0.1.0 installed and filled (UP-01), then 0.2.0 installed over it.
- **State B (fresh):** after state A is done, wipe the emulator again, install `$APK_020` only, finish onboarding through the example project. Read-only checks (U-14.15, U-15.10) and the 0-item checks run here.
- **Run order.** Every item that uses P1, P2, P4 or the UP-18 and UP-19 copies runs in state A, before the wipe: section 2, then SC-G2, SC-G3, SC-G4, SC-S2 and the 0.1.0-map part of SC-S3. Everything else runs in state B (sections 3 and 4, the rest of section 5, section 6). An item that says "state B" but needs a writable project uses a new project `QA Write` made there.

## 1. Global

### GL-01 No crash or ANR in any section
- **Width:** both
- **Steps:** Clear logcat before each section; after it, run `crash`.
- **Expected:** Empty output for every section.
- **Verify:** `$OUT/<section>-crash.txt` is empty. `adb shell dumpsys dropbox --print data_app_crash data_app_anr | grep $PKG` finds nothing new.
- **Blocker:** yes

### GL-02 Version and signing
- **Width:** both
- **Steps:** After the 0.2.0 install, run `adb shell dumpsys package $PKG | grep -E "versionName|versionCode"`.
- **Expected:** `versionName=0.2.0` and a `versionCode` greater than 0.1.0's `1`. `adb install -r` reported `Success` (same key).
- **Verify:** dumpsys output saved to `$OUT/GL-02.txt`.
- **Blocker:** yes (a wrong name misleads; a lower code blocks every upgrade)

### GL-03 Unit tests and lints before the run
- **Width:** none (host)
- **Steps:** With no emulator running: `tools/gw test` (includes `CopyLint`, `MotionLint`, `MicReleaseTest` and every JVM test named in this file).
- **Expected:** BUILD SUCCESSFUL, 0 failures.
- **Verify:** Gradle output and `build/reports/tests` per module.
- **Blocker:** yes (scope §10 step 1)

### GL-04 Visible `TODO_COPY_` text
- **Width:** both
- **Steps:** After every dump in this run: `grep -l "TODO_COPY" "$OUT"/*.xml`.
- **Expected:** No `TODO_COPY_` string is the only label of a button, menu row, switch row or choice. Where the spec gives an interim value (for example `지난 판도 포함`), that value shows.
- **Verify:** grep result. A `TODO_COPY_` string on an action control is a blocker (the user cannot tell what the control does). One in a subtitle, empty state or accessibility name of a control that also shows a clear word is cosmetic (0.2.1).
- **Blocker:** yes for action controls, no otherwise

### GL-05 No em dash or 해요체 in new copy on screen
- **Width:** both
- **Steps:** `grep -lE "$(printf '\342\200\224')|해요|세요\"" "$OUT"/*.xml` over all dumps (the octal escape is the em dash, U+2014; it works in macOS bash 3.2).
- **Expected:** No hits in text added by 0.2.0.
- **Verify:** grep.
- **Blocker:** no
